## 🧭 About Me

I got into QA almost by accident — and stayed because I liked **breaking things** more than just building them.

I started as a **Business Analyst Intern at Zinnia**, writing user stories and sitting in on the calls where product decisions actually got made. That's where a habit stuck with me: I ask **why** a feature exists before I check **how** it works.

Today, I'm a **Software Quality Engineer at Zinnia** on the SDET side, building automation frameworks and CI-integrated test pipelines for insurance policy and annuity platforms — not just running manual test cases.

**A few things I've shipped:**

- 🏗️ Architected an **API regression framework** across 10+ REST endpoints (auth, payload integrity, core workflows), cutting manual validation effort by **50%** and running it inside CI.
- 🧩 Built a **data-driven validation engine** in Playwright + TypeScript that parses conditional rules from Excel and checks **900+ UI fields** against live data across multiple insurance carriers.
- 🌐 Run **cross-browser regression** in Selenium and Python across 3+ environments — usually where the edge cases everyone else misses show up.
- 📋 As a BA intern, validated **15+ API endpoints** with Postman and SQL, and ran **JMeter** performance checks ahead of UAT.

Outside of work, I build full-stack projects to stay close to the code I test — from ticket booking platforms with live payments to real estate marketplaces with token auth and rate-limited APIs.

**Right now**, I'm going deeper into CI/CD-driven automation and exploring where AI genuinely helps testing — self-healing locators, smarter maintenance, fewer flaky tests. Longer term, I want to grow past just building pipelines into shaping how teams think about **testability from day one**, not bolting it on after.

> 💬 If your team's testing actually holds up under pressure, or you're hiring for an SDET who thinks past the test script — I'd love to talk.
